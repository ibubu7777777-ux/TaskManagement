## 2. 選定理由

| 技術 | 選定理由 |
|---|---|
| React + Vite | コンポーネント単位でUIを組み立てる考え方を学ぶため。Viteは起動が速く、現在推奨されている標準的なビルドツールであるため採用 |
| TypeScript | 型を使うことで、データの形（カードの項目など）を明示しながら実装できるため。実務でも標準的に使われている |
| dnd-kit | React上でドラッグ&ドロップを扱う際によく使われる専用ライブラリ。素のHTML5 Drag and Drop APIをReactのコンポーネント構造の中で直接扱うより安全・簡潔に書けるため採用 |
| Tailwind CSS | クラス名を組み合わせてスタイルを当てる方式。CSSファイルを別途書かずに、コンポーネントの中でスタイリングが完結しやすいため採用 |
| Java + Spring Boot | バックエンド開発の学習として、型のある言語でのサーバーサイド実装・DI（依存性注入）・レイヤー分割（Controller/Service/Repository）の考え方を学ぶため |
| Gradle | Spring Bootプロジェクトのビルド・依存関係管理のため。Mavenより設定が簡潔に書けるため採用 |
| PostgreSQL | 実務でもよく使われる本格的なリレーショナルデータベースを使い、実際のDB運用に近い経験を積むため |
| Spring Data JPA + Hibernate | SQLを直接書かずに、Javaのオブジェクト操作としてDBを扱う一般的な構成を学ぶため |

## 3. 構成イメージ

```
ブラウザ（React + TypeScript / Vite / Tailwind CSS / dnd-kit）
        ↕ REST API（JSON）
Spring Boot（Controller → Service → Repository）
        ↕
PostgreSQL（list / card テーブル）
```

- フロントエンドとバックエンドは別プロジェクト・別プロセスとして動かす（フロントは`npm run dev`、バックエンドは`./gradlew bootRun`等）
- マルチユーザー対応（ログイン・ユーザーごとのデータ分離）は対象外
- バージョン管理はGit、リモートリポジトリはGitHubを使用する

## 4. 変更履歴

- 当初はHTML/CSS/JavaScriptのみ（`localStorage`保存）で学習をスタートし、基礎（DOM操作・イベント処理・配列操作）を習得した
- その後、本格的なDB連携・バックエンド開発を学ぶため、React + Spring Boot + PostgreSQL構成に移行することを決定した
- フロントエンドの詳細を、TypeScript・dnd-kit・Tailwind CSSを用いる構成として確定した
